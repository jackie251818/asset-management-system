## 三、前置条件检查

- [ ] 服务器可访问：手机浏览器能打开 `http://192.168.40.247/downloads/apk-update.json`
- [ ] JSON 为 UTF-8 无 BOM，中文显示正常（非乱码）
- [ ] JSON 中 `url` 指向的 APK 可下载（HTTP 200）
- [ ] 服务器 APK sha256 与本地一致（`sha256sum /opt/asset-server/downloads/asset-mgmt-rn-debug.apk`）
- [ ] App 内"服务器"地址配置正确（默认 `http://192.168.40.247`）
- [ ] 测试机「我的 → 关于 → 当前版本」显示正确的版本号

## 四、测试用例

### P0 — 核心链路（必须全部通过）

| # | 用例 | 步骤 | 预期结果 | 实际结果 | 状态 |
|---|---|---|---|---|---|
| 1 | 启动静默检查 | 安装旧版本 App（versionCode 较低）→ 连接服务器 → 启动后等待 6~10 秒，不做任何操作 | 自动弹出"发现新版本"弹窗，显示新版本号与更新说明 | | ☐通过 ☐失败 |
| 2 | 静默失败不打扰 | 断开服务器网络 → 冷启动 App，等待 10 秒以上 | 无任何报错弹窗，App 正常使用 | | ☐通过 ☐失败 |
| 3 | 已是最新（手动检查） | 已装最新版本 → 「我的 → 关于 → 检查更新」 | 弹"已是最新版本"，显示当前版本与最新版本号 | | ☐通过 ☐失败 |
| 4 | 手动检查入口 | 「我的 → 关于」页 | 显示当前版本（如 v1.1.0（2））；「检查更新」行可点击，检查中有加载指示 | | ☐通过 ☐失败 |
| 5 | 下载进度 | 更新弹窗点「立即更新」，观察下载过程 | 切换为下载态：进度条推进、百分比/已下载大小实时刷新，无需其他操作 | | ☐通过 ☐失败 |

## 附：常用核对命令（测试前自检用）

```powershell
# 服务器端哈希核对
& "D:\Program Files\PuTTY\plink.exe" -ssh -batch -pw "<密码>" hmt@192.168.40.247 "sha256sum /opt/asset-server/downloads/asset-mgmt-rn-debug.apk"

# 本地哈希
(Get-FileHash "<本地APK路径>" -Algorithm SHA256).Hash.ToLower()

# JSON 中文乱码排查（PowerShell 直接 .Content 会假乱码，用原始字节验）
$b = (Invoke-WebRequest "http://192.168.40.247/downloads/apk-update.json" -UseBasicParsing).RawContentStream.ToArray()
"first3: $($b[0..2] -join ',')"   # 期望 123,...（即 '{'），239 开头说明带 BOM
[System.Text.Encoding]::UTF8.GetString($b)
```
